# MSRC light sample

Seven of the 32 `.revised` files in the MSR Cambridge `final-trace`
collection, copied byte for byte. They are the smallest files in
`data/MSRC-trace-003/final-trace/`, committed so a clone can exercise the
`revised` loader and the MSRC sweep path without the full 11 GB set.

| File | Requests | Size |
|---|---|---|
| `wdev_3.revised` | 680 | 40 KB |
| `wdev_1.revised` | 1,053 | 61 KB |
| `rsrch_1.revised` | 13,778 | 780 KB |
| `web_3.revised` | 31,378 | 1.8 MB |
| `web_1.revised` | 160,889 | 9.4 MB |
| `wdev_2.revised` | 181,264 | 10.1 MB |
| `rsrch_2.revised` | 207,585 | 11.6 MB |

Counts are the lines of each file, which is one request per line; sizes are
the committed byte counts.

## Format

Headerless, whitespace-separated, 8 columns (`trace.REVISED_COLUMNS`):
`time_s op lba size_blocks seq_or_rand t1 t2 t3`.

- `op` is `RS` (read) or `WS` (write); these traces are write-heavy, so
  `WS` rows dominate every file.
- The loader reads `t1` as `service_ms`; `t2` and `t3` are not used.
- The simulator replays write rows as reads, so hit ratios here are not
  comparable with a read-only workload.

## Usage

```powershell
$env:PYTHONPATH='src'
python -m adaptive_prefetch replay .\data\samples\msrc\wdev_1.revised --format revised
```

`--format revised` is required. `auto` detects a profile from column names,
and these files have no header.

## Provenance and terms

- Source: the MSR Cambridge enterprise traces (D. Narayanan, A. Donnelly and
  A. Rowstron, "Write Off-Loading: Practical Power Management for Enterprise
  Storage", USENIX FAST 2008), in the `.revised` form used by the earlier
  disk results (D17 in `docs/DECISIONS.md`).
- The subset was chosen by file size only. It is not a representative
  sample of the collection and is never a basis for a benchmark claim.
- Copied unmodified: no rows removed, reordered or re-timed. Nothing in
  this directory is generated by a script, so `git status` should stay
  clean; do not edit or regenerate these files.
- Redistribution terms are the source's, not this repository's. See
  `NOTICE.md` and check the dataset's own terms before reusing or
  republishing these files.
