# Web study (E4, plus the E5 sequence-model rows): pre-registration

Written before the full E4 run, so the comparisons and the decision rules
below cannot be chosen after the results are seen (plan C4). It states what
will be compared and how a result will be read. It states no expected
outcome. Every number in the paper's web sections must come from a file
listed here, regenerated by `reproduce.py web`.

## Data and protocol

- RetailRocket events, Kaggle version 2, SHA-256 pinned in
  `src/webprefetch/data.py`. View events only; 30-minute sessions; four
  chronological splits at the 40/60/80% view-time quantiles.
- Split 0 builds the shipped candidate index; split 1 trains the ranker;
  **split 2 (validation) is the only split any choice is made on**; split 3
  (test) is replayed once with every choice frozen.
- Per-session browser caches of 2, 4, 8, 16 and 32 objects. Equal object
  sizes and instant prefetch completion are simulation assumptions.
- The cost of one prefetch, `c`, is an **assumed** number of hit-equivalents.
  Utility is `U(c) = (hits - c * issued) / views`
  (`prefetch_common.utility`). Results are reported at
  c in {0, 0.01, 0.05, 0.25}, and `policy_metrics.csv` also carries U at
  0.001 to 1.0101.

## Selection rule (fixed before the run)

For every scorer, capacity, cost and policy family (fixed depth, adaptive,
cache-aware adaptive, confidence gate, feedback gate), the policy with the
highest validation `U(c)` is chosen; ties go to fewer issued prefetches,
then to the policy name. The grids are those in
`webprefetch.benchmark` (`FIXED_DEPTHS`, `ADAPTIVE_PENALTIES`,
`GATE_THRESHOLDS`, `FEEDBACK_COSTS` x `FEEDBACK_EPSILONS`). Selection is
made **separately at each capacity** (`selection = per_capacity`). The
pivot's rule, which selects at capacity 8 and reuses that choice everywhere,
is reported as `capacity_transfer` and is never a headline row.

## Statistics

- Unit: the test session. Every comparison is paired on the same sessions.
- Interval: paired session bootstrap with 500 resamples, seed 42, the ratio
  estimator `sum(delta) / sum(views)` and a 95% percentile interval
  (`prefetch_common.stats.session_bootstrap`, numpy draws). Each row
  records its session count, reps and seed.
- Verdict for a difference A - B: **A better** if the interval's lower end
  is above 0, **A worse** if its upper end is below 0, otherwise **no
  detectable difference**. No other wording is used for a result.
- No multiple-comparison correction is applied. Only the comparisons marked
  headline below may be stated as findings; every other row is exploratory
  and is labelled as such where it is quoted.

## Decision rules for the paper's claims

1. **Controller.** The paper may say the adaptive controller beats fixed
   prefetching at a capacity only if W1 is "A better" there. If W2 is
   "A worse" the row is labelled "loses to no prefetch", whatever W1 says.
   No statement generalises from one capacity or one cost to others.
2. **Ordering of levers.** For a lever L, let `hi(L)` be the larger of
   |ci_lo| and |ci_hi| of its cap-8 hit-ratio row, and `lo(L)` be 0 if the
   interval contains 0 and otherwise the smaller of |ci_lo| and |ci_hi|.
   The learned predictor (W3, and W8 if present) is called **the smallest
   lever** only if `hi(predictor) < lo(depth)` **and**
   `hi(predictor) < lo(freshness)`. If either inequality fails, the paper
   makes no ordering claim between the predictor and that lever.
3. **Feedback gate.** It is described as improving on the adaptive
   controller only if W6 on U(0.01) is "A better", and as reducing
   prefetching only by the `issued_per_view` values in
   `policy_metrics.csv`; neither is inferred from the other.
4. **Scope.** W7 is reported as an upper bound for cache reuse across a
   visitor's sessions with an unbounded cache; it is not a prefetching
   result.
5. **Capacity transfer.** A difference between `per_capacity` and
   `capacity_transfer` rows is reported as a property of the selection
   protocol, never as a controller effect.
6. If a headline comparison cannot be computed (a missing scorer or
   artifact), the paper reports it as missing; it is not replaced by a
   different comparison.

## Fixed in advance

- The test split is replayed with choices that were all made on validation;
  nothing is re-selected after the test replay.
- Prototype figures from the evaluation phase (for example the pilot
  decomposition deltas) are orientation only and are not cited; only the
  regenerated files are.
- Costs, object sizes and the instant-completion assumption are labelled
  ASSUMED wherever a web number is quoted. Simulated hit ratios are never
  presented as measured latency; that is E6's job.
